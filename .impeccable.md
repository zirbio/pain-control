# .impeccable.md — Pain Control Design Context

## Design Context

### Users
Single user (Silvio), personal chronic pain tracking tool. Used daily for check-ins and periodically for reviewing trends/correlations. Primary context: quick data entry on mobile, deeper analysis on desktop. No external audience — no need for onboarding, marketing polish, or multi-user considerations.

### Brand Personality
**Clinical. Precise. Observational.**

This is an instrument, not an app. It should feel like a well-calibrated scientific tool — something that earns trust through clarity of data presentation, not through charm or decoration. The emotional goal is *control and understanding* — turning chaotic pain experience into structured, actionable insight.

### Aesthetic Direction
- **Theme**: "Warm Observatory" — dark mode only, warm stone/terracotta palette that avoids the cold sterility of typical medical apps while maintaining clinical precision
- **Reference**: Apple Health / Oura Ring — elegant data visualization, smooth gradients, premium feel, information density without clutter
- **Anti-reference**: Generic medical/health apps with bright whites, cartoon illustrations, or gamification elements. No badges, streaks, or motivational messages
- **Color semantics**: Pain intensity drives the color language (sage green → terracotta). Accents are functional, not decorative — amber warns, red alerts, sage reassures
- **Atmosphere**: The UI should feel like a research station at night — focused, quiet, everything in its place

### Typography System
- **Display**: Newsreader (serif) — for metrics and headings. Adds gravitas and readability to numbers
- **Body**: Satoshi (sans-serif) — clean, modern, excellent for labels and data
- **Scale**: 3rem metrics → 1.75rem h1 → 1.25rem h2 → 0.9375rem body → 0.75rem labels → 0.6875rem small
- **Principle**: Numbers are the primary content — they should be large, legible, and immediately scannable

### Design Principles

1. **Data density over decoration** — Every pixel should communicate information or provide necessary breathing room. No ornamental elements. If it doesn't help understand pain patterns, remove it.

2. **Semantic color, never cosmetic** — Colors encode meaning: pain intensity, trend direction, statistical significance. Never use color purely for visual interest. The pain scale gradient (sage → terracotta) is the foundational visual language.

3. **Clinical warmth** — Precise and analytical, but not sterile. The warm dark palette and serif metrics keep it human. A hospital monitor shows data too — the difference is this tool respects that the data represents a person's lived experience.

4. **Glanceable metrics, explorable depth** — Surface level: key numbers visible in 2 seconds. One level down: trends and charts. Deepest: correlations and statistical analysis. Each layer adds detail without requiring the previous to be complex.

5. **Quiet confidence** — Subtle animations that confirm interaction, not impress. Micro-transitions for state changes. No loading spinners that create anxiety — use skeleton screens with warm shimmer. The interface should feel calm and competent.

### Component Patterns
- **Cards**: `bg-bg-secondary border border-bg-tertiary rounded-card` — subtle containers, not loud boxes
- **Hover**: `-translate-y-0.5` + shadow elevation — physical, minimal
- **Data viz**: Recharts/Nivo with muted grid lines (`#44403c`, opacity 0.3), pain scale colors for data points
- **Spacing**: Tailwind default scale, 12px card radius, generous padding (p-4 minimum on cards)
- **Focus states**: `focus-visible:ring-3` — keyboard accessibility without visual noise for mouse users

### Accessibility
- WCAG AA contrast ratios (dark mode makes this easier for text, harder for colored elements)
- Semantic HTML structure
- Keyboard navigation with visible focus indicators
- Pain scale colors designed to be distinguishable by relative lightness, not hue alone
